把“咨询”说清楚，是为了保护双方时间。下面是醴陵真好技术咨询的说明书：做什么、不做什么、聊完通常去哪。

## 两种入口

### 免费 10 分钟

用途：

- 听清你的业务痛点与约束；  
- 判断更接近培训 / 中转 / Agent / FDE / 其他开发；  
- 告知公开价格带与大致周期；  
- 决定是否值得进入深度咨询或直接立项沟通。

不用途：

- 现场出完整技术方案书；  
- 代替你们内部的立项汇报材料；  
- 对未提供任何上下文的问题做拍脑袋架构。

### 深度咨询 · ¥500/小时

用途：

- 多方案比较（例如云端 vs 本地、项目制 vs 驻场）；  
- 场景优先级与分期路线；  
- 风险与合规要点梳理；  
- 帮你准备对内沟通的结构化要点。

可按小时购买，建议先以 1–2 小时把关键分叉谈透，再决定是否继续。

## 咨询桌上最常见的五类议题

1. **我们到底卡在认知、工具、数据还是组织？**  
2. **第一个试点选哪个，别选哪个？**  
3. **预算应该先留给培训还是系统？**  
4. **现有供应商 / 中转 / 开源方案怎么评估？**  
5. **若要私有化，最小可行架构长什么样？**

你不需要五个都准备好。有一个真问题就够开始。

## 你会带走什么

按深度不同，可能包括：

- 问题归类与建议路径（口头或要点纪要）；  
- 场景优先级草表；  
- 粗算的周期与费用带（非正式报价）；  
- 下一步行动清单（本周该找谁、该准备什么数据）。

正式商务报价仍以需求确认后的书面为准，咨询不替代合同。

## 明确不承诺的事

- 不承诺咨询后业务指标必然提升；  
- 不在信息不足时给出虚假精确的人天；  
- 不提供任何违法用途的技术方案；  
- 不把咨询做成强迫捆绑——你可以只听建议，去别处实施。

## 和后续服务的衔接方式

```text
咨询分流
   ├─ 团队不会用 → AI 培训（¥8,000/天 等）
   ├─ 多模型接入乱 → API 中转（按量 + 部署运维）
   ├─ 单场景要私有化 → Agent / RAG 项目制
   ├─ 现场复杂难推进 → FDE（¥50,000/月起）
   └─ 条件不足 → 暂缓，先做数据/流程整理
```

这种分流本身就是咨询价值的一部分。

## 一次深度咨询的示例议程（1–2 小时）

1. 业务痛点与现状系统（20 分钟）；
2. 候选场景打分：价值 × 可行性（25 分钟）；
3. 路径分叉：培训 / 中转 / Agent / FDE（25 分钟）；
4. 风险与合规要点（15 分钟）；
5. 行动清单与是否进入商务评估（15 分钟）。

会后你应能对内讲清：我们建议先做什么、不建议做什么、大概预算带在哪。若还做不到，说明信息仍不足，或需要再约一次专题（例如只谈私有化架构）。

## 咨询纪要的默认颗粒度

深度咨询后，我们通常提供结构化要点（场景排序、路径建议、风险、下一步），而不是长篇白皮书。若你需要面向董事会的长文档，请提前说明，我们按文档工作量另估——以免 1 小时咨询被期待成 30 页报告。
## 咨询之后你可能收到的三种结论

A. 可以启动，建议路径与粗预算带；B. 可以启动，但必须先补数据/权限/人员条件；C. 暂不建议大规模投入，先做轻量验证或培训。三种都是合格结论。只有“无论如何先把预算打过来”才不合格。

对外协作时，我们亦可在征得同意后，把咨询结论同步给你的内部 IT 或业务同事，减少“听过咨询的人”和“真正执行的人”不是同一批导致的信息损耗。企业内部对齐，往往比再多听一小时外部意见更关键。把对齐会议一起排进日程吧。

如果你已经浏览过官网服务与价格页，仍不确定预算该先切哪一块，技术咨询就是为这种分叉准备的。把犹豫说清楚，比把需求包装得很完美更有助于得到诚实建议。
