把“咨询”说清楚，是为了保护双方时间。下面是醴陵真好技术咨询的说明书：**价目、议程、你会带走什么、我们明确不承诺什么。** 若你还在犹豫“要不要先咨询”，见 [为什么先做技术咨询](/articles/why-ai-tech-consulting)——本文只讲怎么约、聊什么、聊完落哪。

## 价目（以公开标价为准）

| 入口 | 价格 | 适合什么时候 |
| --- | --- | --- |
| 免费 10 分钟 | 免费 | 问题还糊、方向还散，先确认该不该继续花时间 |
| 深度咨询 | **¥500/小时** | 要多方案比较、场景分期、风险对齐、对内沟通要点 |

线上 / 线下均可。正式商务报价仍以需求确认后的书面为准——咨询不替代合同。发票与签约细节沟通时说明即可。

### 免费 10 分钟：做什么 / 不做什么

**做：** 听清痛点与约束；判断更接近培训、API 中转、Agent / RAG、FDE，还是其他开发；告知公开价格带与大致周期；决定要不要进入深度咨询或直接立项沟通。

**不做：** 不出完整技术方案书；不代替你们内部立项汇报；不对“零上下文”的问题拍脑袋架构。

### 深度咨询 · ¥500/小时：做什么

多方案比较（云端 vs 本地、项目制 vs 驻场）；场景优先级与分期路线；风险与合规要点；帮你准备对内沟通的结构化要点。

建议先买 **1–2 小时**把关键分叉谈透，再决定是否续约专题（例如只谈私有化架构）。我们见过最浪费的深度咨询，是客户带着空白议程进来，一小时聊成产品介绍会——材料越具体，小时越值钱。

## 1–2 小时默认议程（可裁剪）

| 时段 | 内容 |
| --- | --- |
| 约 20 分钟 | 业务痛点、现状系统、约束（数据敏感、预算量级、上线窗口） |
| 约 25 分钟 | 候选场景打分：价值 × 可行性；明确“先做 / 不做 / 暂缓” |
| 约 25 分钟 | 路径分叉：培训、中转、Agent / RAG、FDE，或组合 |
| 约 15 分钟 | 风险与合规要点（权限、日志、出域、审批） |
| 约 15 分钟 | 行动清单：本周找谁、准备什么数据；是否进入商务评估 |

会后你应能对内讲清三句话：建议先做什么、不建议做什么、大概预算带在哪。若还做不到，说明信息仍不足，或需要再约一次专题——我们会直说，而不是用空话填满剩余时间。

带材料会显著提高密度。最有用的不是精美 PPT，而是：一段真实工单或制度原文、一张现有系统名单、一句“老板最不能接受的失败是什么”。没有这些也能聊，但结论会更多停留在分叉判断，而不是可执行切片。

## 你会带走什么（按深度）

- 问题归类与建议路径（口头或要点纪要）；
- 场景优先级草表；
- 粗算的周期与费用带（非正式报价）；
- 下一步行动清单。

深度咨询后，默认颗粒度是**结构化要点**（场景排序、路径、风险、下一步），不是长篇白皮书。若需要面向董事会的长文档，请提前说明，我们按文档工作量另估——以免 1 小时被期待成 30 页报告。

征得同意后，也可把结论同步给你的内部 IT 或业务同事，减少“听过咨询的人”和“真正执行的人”不是同一批。

## 三种合格结论（A / B / C）

**A.** 可以启动，建议路径与粗预算带；纪要里应能看到粗预算带与下一步负责人。  
**B.** 可以启动，但必须先补数据 / 权限 / 人员条件；应写清缺什么、谁去补。  
**C.** 暂不建议大规模投入，先做轻量验证或培训；应写清暂缓理由与何时重评。

三种都是合格结论。只有“无论如何先把预算打过来”不合格。我们宁可给你 C，也不假装 A——因为后面接实施时，条件不够的项目会把双方都拖进扯皮。

## 明确不承诺

- 不承诺咨询后业务指标必然提升；
- 不在信息不足时给出虚假精确的人天；
- 不提供任何违法用途的技术方案；
- 不把咨询做成强迫捆绑——你可以只听建议，去别处实施。

## 聊完通常去哪（短句分流）

- 团队不会用 → [AI 培训](/pricing)（企业内训 ¥8,000/天起；半天精品课 ¥5,000；公开课 ¥500/人）；
- 多模型接入乱、要账单可见 → API 中转（调用按量；部署与运维按需）；
- 单场景要私有化 → Agent 标准版 ¥50,000 起 / RAG ¥20,000 起（项目制）；
- 多角色工作流 → Agent 企业版 ¥120,000 起；
- 现场复杂、PoC 卡生产 → FDE 入场常驻 ¥50,000/月起；
- 条件不足 → 暂缓，先做数据或流程整理。

分流本身就是咨询价值的一部分。各条线节奏与报价细节，以 [服务价格](/pricing) 及对应服务说明为准。

举例：客服要智能草稿，但一线不会写提示词、工单系统也接不上——常见建议是先培训统一方法，并行评估标准版 Agent 是否值得立项，而不是一上来签最大包。制造现场规则天天变、接口资料不全——更可能指向 FDE，而不是一份锁死范围的项目合同。
